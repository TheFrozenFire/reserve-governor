# `--ir-rocq` compile coverage of governor contracts

Sweep of every governor source file declaring a `contract` or `library`
(pure interfaces excluded), each compiled individually through
`solc-rocq --ir-rocq`. Regenerate with:

```sh
bash formal-verification/scripts/ir-rocq-coverage
```

The script exits non-zero on any failure, so it can be wired into CI.

## What unblocked this

Two prior blockers, both now resolved:

1. **`std::length_error` crash in `Object::toRocq`** (rocq-of-solidity fork).
   Padding to 32-byte boundaries computed `64 - hex_name.size()` as
   `size_t`, underflowing whenever the Yul-side object name
   (`<contract>_<id>` or `…_deployed`) exceeded 32 bytes. Every modern
   OZ-derived contract hit this. Fixed by rounding hex length up to the
   next 64-character (32-byte) boundary:
   `padTo = ((hex.size() + 63) / 64) * 64`. Patched at both
   `libyul/Object.cpp` and `libyul/AsmRocqConverter.cpp`. Branch:
   `TheFrozenFire/rocq-of-solidity:fix/rocq-length-error-and-macos-build`.
   Regression test at `test/cmdlineTests/ir_rocq_long_contract_name/`.

2. **Foundry remappings not visible to solc-rocq**. The wrapper passed
   `--base-path` and `--include-path node_modules` but never expanded
   `remappings.txt`. Source files using `@interfaces/`, `@governance/`,
   `@staking/`, `@utils/`, `@src/` couldn't resolve their imports. The
   wrapper now reads `remappings.txt` from `REPO_TREE` and passes each
   `prefix=path` line as a positional argument to solc (solc's native
   remapping syntax — there's no dedicated flag).

## Output location

The sweep writes per-contract outputs to the canonical path

```
formal-verification/rocq/generated/<ContractName>.v
```

The directory is checked in but its `.v` outputs are gitignored
(see `rocq/generated/.gitignore`). Outputs are local working
artefacts regenerable from current sources; the canonical
artefact is the regen script, not a snapshot.

To regenerate:

```sh
bash formal-verification/scripts/ir-rocq-coverage
```

Add `--keep-logs` to retain per-contract diagnostic logs in the
temp dir, or `--clean` to remove stale outputs (renamed/removed
contracts) before regenerating.

Total disk footprint of a full sweep is ~36 MB. The four heavy
outputs (Deployer, ProposalLib, OptimisticSelectorRegistry,
ReserveOptimisticGovernor) account for ~29 MB of that —
generated bytes that decay on every contract source change and
are the reason the outputs are not committed.

## Optional OZ tier (`--include-oz`)

Run

```sh
bash formal-verification/scripts/ir-rocq-coverage --include-oz
```

to additionally sweep the curated allowlist of OpenZeppelin files
the governor directly imports (18 files: 12 from
`@openzeppelin/contracts`, 6 from `@openzeppelin/contracts-upgradeable`,
all version-pinned at 5.4.0). The allowlist lives in the script as
`OZ_ALLOWLIST`. Pure-interface files are excluded — solc emits no IR
for them, and the same is true for the abstract `…Upgradeable` bases
(they round-trip through `--ir-rocq` but produce trivial output
because they're not deployable in isolation).

OZ outputs land under `rocq/generated/oz/<RelPath>.v` to avoid
colliding with the governor sweep (e.g.
`rocq/generated/oz/contracts/access/AccessControl.v`). The `oz/`
subtree is gitignored. OZ failures do **not** gate the script's
exit code — the OZ tier is diagnostic, surfacing
`shallow_embed.py` gaps catalogued in
`notes/shallow_embed_oz_gaps.md`.

Current OZ tier on the patched fork: **18 / 18 PASS** at the
`--ir-rocq` stage (deep IR generation). Concrete contracts emit
real IR (ERC1967Proxy: 4 306 lines, AccessControlEnumerable:
1 838 lines, GovernorUpgradeable: 2 764 lines); abstract bases
emit essentially empty IR (Initializable: 2 lines, ERC20Upgradeable:
16 lines) which is the correct solc behaviour. The real surface area
for gaps is the next pipeline stage (shallow embed → coqc), which
`notes/shallow_embed_oz_gaps.md` walks through.

## What this coverage doesn't yet prove

- **The generated IR isn't fed into `coqc` by the main build.**
  Each `.v` output contains multiple top-level
  `Definition codes` declarations (one per compilation unit
  pulled into the source), which collide under `coqc <file>.v`
  with `codes already exists`. Fix is upstream-fork: scope each
  unit into its own `Module`. Until then, the IR is locally
  regenerable and serves as the substrate for the
  equivalence-proof workstream under `proofs/equivalence/`, but
  it is NOT listed in `_RocqProject`'s main build.
- **No semantic equivalence yet.** Compile-passing only says
  solc-rocq produced *some* IR. Whether that IR faithfully
  captures each contract's storage layout, ABI, and runtime
  behaviour against the hand-written `rocq/simulations/` is the
  business of `proofs/equivalence/<ContractName>.v` files, which
  do not yet exist. `Audit.v` Caveat-5 documents the gap; the
  scaffolding under `proofs/equivalence/README.md` describes
  what closing it looks like.

## Why this matters anyway

A compiling `--ir-rocq` pipeline across every governor contract
is the floor for the equivalence-proof workstream. Any regression
in the fork or in the remapping plumbing surfaces immediately
when the sweep is re-run: a fresh `ir-rocq-coverage` either
exits 0 with 22/22 PASS or fails loudly on the offending
contract.
